1. Executive Summary & Core Innovation

Traditional Web Application Firewalls (WAFs) rely on static signature matching and blunt connection termination (TCP resets / IP drops). While effective against simple script-kiddie tools, they suffer two fatal weaknesses:

  1. Reconnaissance Alerting: Dropping a connection informs an intelligent adversary or LLM web scraper that their probe hit a defensive boundary, allowing them to mutate payloads or rotate IPs.
  2. Resource Asymmetry: The defender spends CPU and bandwidth inspecting traffic while the attacker harvests corporate databases freely.

This project implements an Active Deception Architecture. Instead of blocking adversaries outright, the application monitors behavioral telemetry in real-time. When suspicion exceeds the threshold (Score ≥ 80/100), the system dynamically traps the attacker inside a synthetic honeypot data stream without alerting them. The adversary wastes compute, time, and LLM context window tokens harvesting poison records, while 100% of real sensitive corporate data remains fully protected.

3. The 8 Behavioral Heuristics & Scoring Engine

The threat score is calculated across a 60-second sliding time window according to the formula:

Total Suspicion Score = min(100, ∑ [S1 + S2 + S3 + S4 + S5 + S6 + S7 + S8])
Signal # Heuristic Signal Max Points Mathematical Calculation Rule Threat Meaning
S1 Sequential IDs 20 pts min(20, (consecutive_ids / 15) * 20) Iterating /employees/1..N sequentially indicates automated database dumping.
S2 Deep Pagination 15 pts min(15, (max_page_requested / 10) * 15) Browsing past page 10. Legitimate humans rarely inspect deep pagination.
S3 Failed Logins 15 pts min(15, (failed_401_count / 5) * 15) Multiple 401 Unauthorized errors indicate brute force or credential stuffing.
S4 Sensitive Paths 10 pts min(10, (distinct_sensitive_paths / 4) * 10) Probing sensitive endpoints like /salary, /admin/security, or /audit.
S5 Keyword Searches 10 pts min(10, (sensitive_keywords / 10) * 10) Search queries looking for password, salary, admin, or leak.
S6 Request Velocity 20 pts min(20, (requests_per_minute / 60) * 20) High-speed automated traffic exceeding human reading capability (≥ 60 requests/min).
S7 Fast Request Intervals 5 pts min(5, (gaps_under_0_3s / 10) * 5) Inhuman sub-second gaps between consecutive HTTP requests (< 300 ms).
S8 Automated User-Agent 5 pts Flat 5 pts if User-Agent matches bot / curl / python Identifies non-browser client libraries (e.g. curl, python-requests, httpx).

4. The Web Application: employee_app

A. Backend Architecture

  • Framework: FastAPI (Python 3.14 / ASGI asynchronous high-throughput engine).
  • Dual-Database Design:
    • employee.db: Real corporate records (employees, salaries, departments, attendance).
    • security.db: Completely isolated security telemetry (access logs, blocked IPs, system metrics, honeypot sessions).
  • SQLite WAL Mode: Both databases operate under Write-Ahead Logging (PRAGMA journal_mode=WAL;) for simultaneous multi-reader and multi-writer concurrency.
  • Authentication: JSON Web Tokens (JWT) using HMAC-SHA256 (HS256) and PassLib Bcrypt password hashing.

B. Self-Registration & Role-Based Access Control (RBAC)

The system supports dynamic self-registration for three distinct roles without needing hardcoded scripts:

  1. Employee (role: employee): Self-service portal (/dashboard/me). Views personal profile, department, daily attendance, and individual salary slips.
  2. HR Manager (role: hr): Enterprise portal (/dashboard/hr). Manages company personnel, departments, and attendance records.
  3. Security Administrator (role: admin): SOC monitoring console (/admin/security-dashboard). Inspects live suspicion scores, views the 8 heuristic breakdowns, executes 1-click IP suspensions, and tracks honeypot telemetry.

5. Attacker Simulator & LLM Context Exhaustion

A. Simulator Scenarios

Scenario Target Behavior Expected Score Outcome
normal_browse Legitimate human traffic, random delays, normal browser headers. 8–10 / 100 (NORMAL) Normal access granted; real data returned.
pagination_only Deep pagination scraping through /employees?page=N. 35–50 / 100 (ELEVATED) Elevated alert on dashboard.
rapid_enumeration Rapid sequential ID scraping (/employees/1..N) with 0 delay. ≥ 80 / 100 (TRAP) Intercepted and fed synthetic honeypot records.
mixed Reconnaissance + failed credential brute-forcing + scraping. ≥ 80 / 100 (TRAP) Score surges; trapped and logged.
full_lifecycle Full attack cycle: reconnaissance → failed login → enumeration → trap → block. 85–100 / 100 (BLOCKED) Attacker trapped and temporarily suspended.
context_exhaustion Consumes infinite decoy data stream to saturate LLM context buffer. 100 / 100 (SATURATED) Token meter records context window saturation.

B. LLM Token Metering & Context Saturation

Autonomous scrapers frequently leverage LLMs (e.g. GPT-4, Claude) to parse stolen web pages. LLMs have strict Context Windows (e.g. 8k, 32k, or 128k tokens).

The project integrates token_service.py utilizing OpenAI's tiktoken library with the cl100k_base Byte-Pair Encoding. The honeypot generates vast, structurally convincing synthetic JSON streams that overwhelm the LLM's prompt buffer, exhausting its memory and multiplying API costs for the attacker.

8. Viva Voce & Demonstration Walkthrough

  1. Start App: cd employee_app && ./venv/bin/uvicorn main:app --reload --port 8000.
  2. Show Registration: Open http://127.0.0.1:8000/register, select HR Portal, register account, observe automatic redirect to /login with pre-filled username.
  3. Open SOC Dashboard: Open http://127.0.0.1:8000/admin/security-dashboard in a second tab.
  4. Demonstrate Normal Score (< 80): Run ./attacker_simulator/.venv/bin/python3 simulator.py --scenario normal_browse --requests 10. Show dashboard score stays green (~8-10 / 100).
  5. Demonstrate Threat Score (≥ 80) & Honeypot: Run simulator.py --scenario full_lifecycle --requests 50. Show score surge past 80, turn red (TRAP), and fake logs generated in employee_app/fake_logs/.
  6. Demonstrate Browser 403 Block: Click the red 🚫 Block button next to 127.0.0.1 on the dashboard. In client tab, refresh to reveal the animated 403 screen with pulsing shield and live ticking countdown timer.
  7. Run Comparative Benchmark: Run python3 run_experiments.py to demonstrate 100.0% data protection.
